Obsidian Vault Second Brain 改善報告

發布：2026-09-25｜範圍：Obsidian Vault 作為 AI agent 的可讀、可追溯記憶層

結論：Vault 的定位、讀取規則、輸出邊界、索引與每週探索流程都已有可執行的規則與實際產物；缺的是一份公開、可讀的交付報告。這一頁補上交付，不納入任何原始筆記、私人路徑或敏感內容。

這次改善的目標

不是把 Obsidian 變成每天塞資訊的摘要箱，而是讓 agent 在需要個人脈絡時，能先找得到使用者的興趣、過往決定、專案線索與已驗證的操作經驗；回答後，也能留下可回查的輸出。

先查再答先用輕量索引定位，再讀真正相關的筆記；不把整個 Vault 一次塞進對話。
輸出先審核agent 的新內容先寫到專用輸出區，不直接改寫長期知識或專案真相。
可追溯每個非顯而易見的判斷要附來源筆記；過時或重複資料先提出 review，不靜默刪除。
每週、小量以每週一次的興趣探索取代大量日報，提供新觀點、反方觀點與一個 15 分鐘可消化的選項。

已落地的能力

能力實作方式已驗證的證據
Agent 可讀的共同規格Vault 有一份短版 steering note 與一份完整操作說明：定義讀取順序、可寫區、禁止直接改動的區域，以及每個輸出的來源引用規則。操作規格明確把 Vault 定位為「AI agent brain / interest graph」，並指定只在輸出區新增草稿。
輕量索引與興趣快照索引提供檔案、標題、主題、摘要等定位資訊；興趣快照顯示近期活動與主題，供 agent 在回答前縮小範圍。2026-09-25 的快照已列出近期 curation、weekly scout、Hermes 操作知識及主題訊號。
主動取用、但有上限對偏好、歷史決策、研究方向與 Vault 工作流程，agent 要先取用索引；每次只讀一份地圖檔與至多三份相關原始筆記。這條規則已記錄為 active operating loop，避免「有 Vault 卻只在被提醒時才查」與上下文膨脹兩種問題。
每週興趣探索從 Vault 的實際訊號找 1 個興趣主線、3 個值得注意的新觀點、1 個反方視角、3 個推薦材料與 1 個 15 分鐘選項。已有 2026-09-21 的手動 weekly-interest-scout 產物；它明確標出這不是新建或修改排程。
角色分工與可回查性一般 agent 可產出草稿、review 與連結建議；長期 wiki 知識的 promote 交由 curator 決定。操作規格與 active operating loop 均保留「先 review、再 promote」的分界。

目前看到的效果

  • Vault 不再只是倉庫：近期索引同時包含研究、agent 操作教訓、curation 與週期性輸出，因此後續工作可以連回「之前為何這樣做」。
  • 個人化有可檢查的來源：不是憑對話印象猜興趣；推薦或判斷需要能回到具體筆記核對。
  • 降低錯誤擴散：長期知識不由一般流程直接覆寫；過時內容以 review 提出，保留原始脈絡與更正空間。

仍需誠實面對的缺口

  • 索引欄位還不完整：部分既有條目缺少明確的 interest_signal 或 claim，目前只能輔以路徑、主題與近期性判讀；這會降低自動推薦的精準度。
  • 每週探索先以手動產物驗品質：目前操作規格保留了自動排程，但尚不應把「有規格」誤稱為「已持續自動運作」。
  • 公開報告與私人記憶必須分開：本頁只交代架構、規則與可驗證狀態；不公開 Vault 原始內容、私人檔案位置或敏感資訊。

接下來怎樣才算真正有用

  1. 每次涉及偏好、既有決策或 Vault 工作流程的問題，先做小範圍檢索，再引用實際筆記回答。
  2. 新產出的 lesson、review 或研究草稿，重建索引後確認可被找到。
  3. 先累積並檢查 1–2 次每週興趣探索的品質，再決定是否啟用固定自動排程。
  4. 由 curator 審核要不要把草稿提升為長期 wiki 知識，避免未驗證內容變成「永久記憶」。
